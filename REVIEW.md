# REVIEW.md

Defects found in the starter `app/main.py` (helpers and endpoints).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` (module level) | Created without `tz_aware=True`, so every datetime read back from MongoDB is naive (no time zone). Mixing it with an aware datetime raises `TypeError`, and naive values are silently treated as local time by `datetime` methods. | Read a log and compute `punch_out - datetime.now(timezone.utc)`: `TypeError: can't subtract offset-naive and offset-aware datetimes` → 500. | `MongoClient(uri, tz_aware=True, ...)`; all datetimes in the app are UTC-aware. |
| 2 | `MongoClient(...)` (module level) | No `serverSelectionTimeoutMS`: when MongoDB is down every request blocks for the 30 s default before failing. | Stop MongoDB, call any endpoint: the request hangs about 30 s, then returns 500. | `serverSelectionTimeoutMS=3000`. |
| 3 | `health()` | Always returns 200 without touching MongoDB, but the contract says 200 only when MongoDB answers, else 503. | Stop MongoDB: `/health` still says `ok`, so the runner would start testing a dead app. | `client.admin.command("ping")`; `PyMongoError` → 503 `{"detail": ...}`. Test: `test_health_returns_503_when_mongo_is_down`. |
| 4 | (whole file) | No indexes are created. The grader's DB only has `_id`, so uniqueness is not enforced and every list/analytics query is a collection scan. | `db.attendance_logs.getIndexes()` shows only `_id_`; explain of `/attendance` shows `COLLSCAN`. | `ensure_indexes()` run from the FastAPI `lifespan` at startup (idempotent). Indexes are added per feature. |
| 5 | `EmployeeIn` model | No validation at all: any string is accepted for `emp_code`, `email`, the shift times and `joined_on`, and `shift_start == shift_end` (a zero-length shift) is allowed. | `POST /employees` with `{"emp_code": "x", "email": "nope", "shift_start": "25:00", "joined_on": "2026-02-30", ...}` → 201. | `EmployeeCreate` with `Field(pattern/min_length/max_length)` from the contract, a `DateStr` type that also checks the date is real, and a `model_validator` rejecting equal shift times → 422. |
| 6 | `create_employee` | Check-then-insert (`find_one`, then `insert_one`) with no unique index: two concurrent creates both pass the check and both insert. | 20 parallel identical creates → **20× 201** and 20 documents with the same `emp_code` (reproduced with 50 ms of simulated DB latency, as on a remote cluster). | Unique index on `emp_code`; just `insert_one` and map `DuplicateKeyError` → 409. Test: `test_parallel_duplicate_creates_yield_exactly_one_201`. |
| 7 | `create_employee` | `created_at = datetime.now()` is naive local time. PyMongo stores naive datetimes as if they were UTC, so on an IST machine the stored instant is 5h30 in the future. The response also returns it as an ISO string, while the contract wants epoch ms. | Create on an IST laptop → stored `created_at` is 5h30 ahead of the real time; response has `"created_at": "2026-...T..."` instead of an int. | `datetime.now(timezone.utc)`; responses go through `serialize_employee()` → `to_ms()`. |
| 8 | `list_employees` | `skip = page * page_size`: page 1 skips the first page. | 6 employees, `GET /employees?page=1` → `items: []`, `total: 6`. | `skip((page - 1) * page_size)`. |
| 9 | `list_employees` | `total = count_documents({})` ignores the department filter. | `?department=Sales` with 2 Sales of 5 employees → `total: 5`. | `count_documents(q)` with the same filter as the query. |
| 10 | `list_employees` | No sort: order is whatever MongoDB returns (insertion order, not guaranteed), but the contract wants `emp_code` ascending. Paging over an unsorted result can repeat or skip rows. | Insert EMP0004 before EMP0001 → list returns EMP0004 first. | `.sort("emp_code", 1)`, backed by the unique `emp_code` index and `{department, emp_code}` for filtered lists. |
| 11 | `list_employees` | `page` / `page_size` are not bounded: `page=0` is accepted, a negative page gives a negative skip (PyMongo raises `ValueError`), and `page_size=10000` is accepted. | `GET /employees?page=-1` → 500; `?page=0` → 200; `?page_size=101` → 200. | `Annotated[int, Query(ge=1)]` and `Query(ge=1, le=100)` → 422. |
| 12 | `list_employees` | Returns `created_at` as a datetime (serialized as an ISO string) instead of epoch ms. | Seeded employee → `"created_at": "2026-01-05T04:30:00"`. | `serialize_employee()` converts to ms (`1767587400000`). |

## Looked at and decided were not defects
- `load_dotenv()` is called without `override=True`. That is correct: real environment variables keep priority over `.env`, as the contract requires.
- `doc.pop("_id", None)` after `insert_one` in `create_employee`: correct, because `insert_one` adds `_id` to the dict it is given. (The new code no longer needs it: `serialize_employee` builds the response from named fields.)
- `find(q, {"_id": 0})` in `list_employees` correctly hid `_id`; the new serializer does the same by only copying named fields.
